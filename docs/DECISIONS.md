# Decisions

The lasting choices behind AIRA, with why they were made. Check here before reversing one. Add a row in the pull request
that makes a new decision.

## Architecture

| Date       | Decision                                                                                                                                                             | Why                                                                                                                                                                            |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 2026-11-15 | The core is a new TypeScript service on Node 24. The existing Python chatbot code is retired at cutover.                                                             | The designs AIRA adopts are proven in TypeScript, and both maintainers can read a small typed codebase.                                                                        |
| 2026-11-15 | Hermes Agent stays as the WhatsApp transport at its pinned commit. It is not upgraded.                                                                               | 55 of 67 local patches fail on current upstream, and upstream ships the same WhatsApp library.                                                                                 |
| 2026-11-15 | The core attaches at the seam that exists today: an OpenAI-compatible endpoint on `127.0.0.1:9881` that Hermes calls as a custom model provider.                     | Cutover and rollback are one address change. No new Hermes patch is needed to attach.                                                                                          |
| 2026-11-15 | Hermes's fallback provider list is emptied. The core always returns a deliverable reply.                                                                             | It removes the second agent loop, the duplicate tool set and the second voice.                                                                                                 |
| 2026-11-15 | One turn runner interface with two implementations: an API runner and a subscription runner.                                                                         | The prompt, tools and cleaning chain stay identical on both transports (PRD FR-32).                                                                                            |
| 2026-11-15 | The API runner uses Google's Agent Development Kit for the model loop and tool calls.                                                                                | It gives callbacks at every stage the core must control, and the maintainers know it.                                                                                          |
| 2026-11-16 | Every tool is atomic: one action, one transaction, safe to repeat. Tools that bundled several actions are split.                                                     | The old tools reported failure after a save worked, forgot three facts at once, and hid several actions behind one name.                                                       |
| 2026-11-16 | A text command names the tool and the model fills its arguments from free text. One command per message.                                                             | Nobody learns an argument syntax on a phone. The slash still guarantees which tool runs, and code still decides whether it ran.                                                |
| 2026-11-16 | A tool chain ends at 4 calls or 15 seconds of tool time, whichever comes first.                                                                                      | The old system averaged about 3 calls on a tool turn. A count alone ignores that one slow call costs more than three fast ones.                                                |
| 2026-11-16 | The core reads chat, sender and message id from the gateway's scope marker. The scope stamp is switched on at cutover.                                               | Measured: the gateway sends no id in any header. The marker is the only place the message id reaches the core.                                                                 |
| 2026-11-16 | The core decides reply bubbles and marks them with a break line. The gateway's bubble patch delivers them, through a helper module AIRA ships.                       | The patch already sends bubbles in order with typing pauses. The old helper decided by the old core's bindings.                                                                |
| 2026-11-16 | A sticker is a `MEDIA:` line in the reply. One new gateway patch sends a `.webp` from a `stickers/` folder as a sticker.                                             | The gateway sends files after the text, so order holds. The core's container cannot reach the host's bridge port without host networking.                                      |
| 2026-11-16 | The core sends no late reply. When it cannot be reached, the gateway sends the default pack's unavailable line through a helper module AIRA ships.                   | Measured: the gateway retries the same request for 22 s to 50 s, then answers the chat itself. A late reply would come out of order.                                           |
| 2026-11-16 | Of the 68 gateway patches, 44 stay, 20 become dead code left until the next re-pin, 2 follow the owner tools and 2 are removed.                                      | The core now owns replies, tools and failures. Leaving dead patches in place keeps cutover small.                                                                              |
| 2026-11-16 | The core stores each user message in its window when the message arrives, and a turn claims the messages it answers.                                                 | The window is then the durable input of a turn: a restart, a merged batch or a message that arrives mid-turn loses no text and answers nothing twice.                          |
| 2026-11-16 | One merged turn returns its reply for the newest message only. The other merged requests get `NO_REPLY`.                                                             | The gateway would send a reply once per request. One turn must send one reply.                                                                                                 |
| 2026-11-16 | When the user content holds scope markers that disagree, the request is refused.                                                                                     | Message text can hold a forged marker. Refusing a disagreement keeps identity from ever coming from message text.                                                              |
| 2026-11-16 | A turn with nothing to send returns `NO_REPLY`. This reverses the earlier row that returned empty content.                                                           | Measured: the gateway reads empty content as a failed model, asks 3 more times, then sends its own notice. It sends nothing for `NO_REPLY`.                                    |
| 2026-11-16 | A scheduled turn is a request with tools, no scope marker and the core's tag after the gateway's cron block. Its chat comes from the core's job row.                 | Measured: the gateway's schedule sends no marker and puts its own block before the job's text. A tag in text is not identity; the job row is.                                  |
| 2026-11-16 | A request with no tools is an auxiliary chore, even when its text holds scope markers.                                                                               | Measured: title and summary requests quote the transcript, markers included. Read as turns, they would answer a message twice.                                                 |
| 2026-11-16 | A request with tools, no marker and no known tag gets `NO_REPLY` and a `gateway_unmarked` record. The gateway's skill review is switched off at cutover.             | Measured: the gateway's skill review sends such requests. An error status would make the gateway retry; silence with a record still shows a scope stamp that is off.           |
| 2026-11-16 | Quote and media notes before a marker are taken out of the message text and kept as the message's quote and attachments.                                             | Measured: the gateway writes them in the user text. Read as text, a quote was taken for an earlier unanswered message.                                                         |
| 2026-11-16 | AIRA's `brain.bubbles` splits only at the core's break lines and reads no chat setting. An interrupt drops the unsent bubbles, receipts included.                    | The core answers every chat after cutover and decides the bubbles. The old helper's receipt marks belonged to the old core.                                                    |
| 2026-11-16 | AIRA's `brain.failure` finds the data volume through `AIRA_HOST_DATA_DIR` in the gateway's `.env`.                                                                   | The gateway's environment is already backed up and restored at cutover and rollback. A file beside the module would be one more thing to install.                              |
| 2026-11-16 | AIRA's gateway patches live in `deploy/gateway/patches.py`, run after the old core's reapply script. The older patches stay in that script until the next re-pin.    | Moving the whole 268 KB script would mean scrubbing it for a public repository. A small script of AIRA's own patches is reviewable and changes nothing that works.             |
| 2026-11-16 | The unregistered reply-prefix test edit is removed and the upstream test restored. `aira-trace` is removed at cutover, not before.                                   | Measured: no gateway code writes the quote order the edit expects, and it fails. Removing the trace on live needs a bridge restart, which cutover does anyway.                 |
| 2026-11-16 | A quoted message is stored beside the message that quotes it, not in its text, and the model sees it as a labelled block. Forget clears quotes of a cleared message. | Memory accepts a fact only from the person's own words. A quote inside the text would let another member's words count as the sender's, and would keep a forgotten text alive. |
| 2026-11-16 | For a skill-style command, the named tool is the only tool offered until it has been called.                                                                         | The command decides the tool. Offering nothing else makes that a property of the request, not a hope about the model.                                                          |
| 2026-11-16 | Code writes the answer of a direct command in plain words until packs carry templates for it.                                                                        | The pack contract has no template for a command answer. A plain list is better than no `/help`, and it holds no persona text.                                                  |
| 2026-11-16 | Before `/cancel` and `/forget`, code shows the model the rows it may choose from.                                                                                    | A removal must name exactly one row by id. The model cannot name an id it has not seen.                                                                                        |

## Data

| Date       | Decision                                                                                                                                              | Why                                                                                                                                                                   |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 2026-11-15 | One SQLite file is the canonical store. One process writes it.                                                                                        | The memory faults came from several writers on unlocked text files.                                                                                                   |
| 2026-11-15 | A character pack on disk is the only source of persona text.                                                                                          | Persona text hard-coded in program code cannot differ per chat.                                                                                                       |
| 2026-11-15 | Chat settings live in the database, in a three-level hierarchy. Deployment settings live in `config.yml`. Secrets live in `.env`.                     | Settings need transactions, validation and a change record. Deployment values need review in git.                                                                     |
| 2026-11-16 | SQLite stays the system of record. DuckDB is the analysis engine, reading verified snapshots and a Parquet archive, never the live file.              | The core does many small transactions that must each survive a crash. Reports want aggregates across files. Each engine does the job it was built for.                |
| 2026-11-16 | Every unit of work in flight is a database row with a state. A restart resumes it or fails it by rule.                                                | The old system kept work in memory and in files, so a restart lost it or repeated it.                                                                                 |
| 2026-11-16 | A verified, encrypted copy of the data lives off the host, at most 15 minutes old, and a restore is rehearsed.                                        | The host has lost its disks before. Copies on the same disk are lost with it.                                                                                         |
| 2026-11-16 | A failed deploy returns to the previous image without restoring data. This reverses the earlier step that restored a backup when a migration had run. | A restore would drop every turn written since the snapshot. Migrations now keep the previous release working instead.                                                 |
| 2026-11-16 | `inbound_message` is keyed by the chat and the gateway's message id, not by the message id alone.                                                     | A message id is unique only inside its chat. With the chat in the key, a repeated id can never return another chat's stored reply.                                    |
| 2026-11-16 | A turn's reply is stored once, as its assistant row in `session_message`. A repeated request reads it from there.                                     | Verbatim text may live in two tables only. A copy on `inbound_message` or `turn` would be a third.                                                                    |
| 2026-11-16 | Files on the data volume are tracked in a `file` table, owned by Persistence.                                                                         | The contract promised a database row per file but named no table for it.                                                                                              |
| 2026-11-16 | A release starts on a schema that holds migrations it does not know.                                                                                  | An image rollback runs the previous release on the newer schema. Refusing to start would turn every rollback into a restore.                                          |
| 2026-11-16 | At start-up every job lease returns to the queue, expired or not.                                                                                     | One process writes the file, so every earlier lease owner is gone. Waiting for the expiry would only delay the work.                                                  |
| 2026-11-16 | A snapshot is one file with a rollback journal, and the recovery pass empties `snapshots/` of everything else.                                        | The Restart suite found that a kill during verification left a stray file beside a snapshot.                                                                          |
| 2026-11-16 | Every table uses an internal chat id and subject id. Only `chat` and `identity` hold a WhatsApp id.                                                   | Record tables must not hold WhatsApp ids. One mapping at the door keeps them out of every other table and log.                                                        |
| 2026-11-16 | A chat seen for the first time is stored as `pending` and gets no reply until it is set `active`.                                                     | The admission rules refuse an unknown chat. A pending row lets the owner see it and switch it on, and lets records name it.                                           |
| 2026-11-16 | A mutating tool changes state only through one `commit` call that also stores the call's result and its receipt.                                      | One transaction per state change, a receipt only after the commit, and a repeat by call id are then properties of the registry, not promises each handler must keep.  |
| 2026-11-16 | A reminder row commits before the call to the gateway's schedule. Start-up reconciliation creates a missing job.                                      | A transaction cannot span a network call. Writing the row first means a failed call leaves a reminder that is recreated, never one that is lost.                      |
| 2026-11-16 | `main` and `fallback` carry token prices in `config.yml`, used when the provider reports no cost.                                                     | Without a price or a reported cost, the spend cap could never be reached.                                                                                             |
| 2026-11-16 | Every forget is a barrier: the chat's pending and running memory work from before it applies nothing.                                                 | The message that states a fact stays in the window. Without the barrier, the next extraction would store the fact again right after it was forgotten.                 |
| 2026-11-16 | `forget` removes a fact only when it is named by id. A search returns candidates and removes nothing.                                                 | A search can match the wrong fact, or another member's. The contract already forbids a match by a shared word.                                                        |
| 2026-11-16 | Forgetting a fact also clears its older versions, its key, the episode summary of the same job, and the text of the message that supported it.        | Each of those can show the forgotten fact again. Replies, snapshots and the off-host copy keep it for their stated retention only.                                    |
| 2026-11-16 | An extracted fact must quote one message written by the person it is about, and every number in it must be in that message.                           | A quote check against the whole episode accepts AIRA's own words and another member's words, and lets a model invent a number.                                        |
| 2026-11-16 | The database runs with `secure_delete` on, and retention always keeps the newest window row.                                                          | A cleared value must not stay in free pages. An empty window table would reuse message ids, and memory would skip new messages without a sign.                        |
| 2026-11-16 | Every forget is a barrier: it moves the chat's memory cursor to its newest message and ends the chat's queued memory jobs.                            | Otherwise a fact a member asked to forget could be extracted again from messages that were waiting. The cost is that other facts in those messages are not extracted. |
| 2026-11-16 | Only a forget that names a fact by its id removes anything. A forget with words to search for returns the matches.                                    | A search can match the wrong fact. The person, not a ranking, says which fact goes.                                                                                   |
| 2026-11-16 | The judge's model id is the key `judge.model`, empty by default. With no judge, memory admits nothing and `note` is refused.                          | The thresholds are chosen against one model version, so the id must be explicit. A missing judge must fail closed.                                                    |

## Deployment

| Date       | Decision                                                                               | Why                                                                         |
| ---------- | -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| 2026-11-15 | A tagged release builds one container image. The host pulls and deploys it on a timer. | Updates cannot be forgotten, and no outside system holds a key to the host. |
