# Dashboard state ownership

| Field group                                              | Read and write authority                                                                                                                        | Editability and activation                                                                                                     | Conflict and recovery                                                                                                                                 |
| -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| Registered settings at global, type or chat scope        | Core SQLite setting rows. Validate with definitionFor in src/settings/keys.ts. Read effective chat settings and PUT /api/settings.              | Runtime. Resolve chat, type, global, then registry default. A null write removes the row. Actor is site.                       | Check an opaque revision within the write transaction. Commit change and audit together. Reload on conflict and preserve draft.                       |
| Chat status and label                                    | Core chat row through /api/chats/:id/status and /label. Gateway directory supplies display metadata.                                            | Runtime. An active chat must have a valid effective binding.                                                                   | Check the expected record version. Refetch the saved row. Keep gateway and owner labels distinct.                                                     |
| Character card, fixed lines, expressions and tool footer | Pack loader reads repository and data packs. Restricted writer owns editable data packs. Existing footer write uses /api/characters/:id/footer. | Repository pack is read-only. Create a writable copy for edits. Publish a fully validated revision before next-turn selection. | Stage on the same filesystem. Compare source bytes again under writer coordination. On invalid input preserve bytes, draft and last applied revision. |
| Deployment configuration                                 | Versioned configuration, startup schema, installed process                                                                                      | Deploy/restart only. Show sanitized effective and applied revisions. Secrets stay on host.                                     | Revert through the deployment runner. Verify the installed revision and health.                                                                       |
| Host settings, files, notices and service control        | Host owner API through /owner-api/. Owner credential travels in the protected header.                                                           | Host-owned. Confirm service state and read back the saved target.                                                              | Preserve drafts and distinguish refusal from unknown outcome. Reconcile at the owner service.                                                         |
| Markets and routines                                     | Core authenticates against host and applies market file or scoped scheduling operation.                                                         | Runtime. Preserve unrelated recipients, hours, prompts and scope.                                                              | Compare submitted prior values for market replacement. Reconcile scheduler acknowledgement and scope binding.                                         |
| Appearance                                               | Owner device storage                                                                                                                            | Immediate local preference. Validate restored theme, rail and backdrop values.                                                 | Restore defaults locally when obsolete. Exclude credentials from preference migration.                                                                |
| Owner-authored text submission                           | Durable core identity, one resolved target and gateway receipt                                                                                  | Owner confirmation starts a single dispatch. Gateway acknowledgement is the strongest positive outcome.                        | Lookup existing identity before retry, including after process restart. Preserve unknown outcome on lost acknowledgement.                             |

The revision and recovery requirements above describe the dashboard contract. The legacy settings PUT accepts
level, scope, key and value without an expected revision. Existing tokenless core routes and protected host routes
require separate authorization coverage at the server before the dashboard cutover.

## Field-level sources

Each row of [the registered setting keys](data.md#setting-keys) uses the SQLite setting protocol above, including
dynamic MCP and platform keys. GET /api/settings?level=&scope= returns the raw scope. A consumer needs the
specificity of the winning value as well as its value. setSetting and unsetSetting record old/new values in
setting_change. A label change records only that a label changed. Restore through a validated new write.
For a chat with no local override, a change at type or global scope can invalidate an effective-value draft.

| Host or device fields                                             | Existing operation                                                        | Existing validation or recovery                                                                                                                        |
| ----------------------------------------------------------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Model defaults, provider endpoint, effort, search, learning       | Host models, models_probe, models_refresh, search and learning operations | Keep probes read-only. Distinguish saved host models from the core model role.                                                                         |
| Avatar, voice provider, voice language, mute and home integration | Host avatar, tts_provider, tts_lang, tts and home operations              | Never return home credentials as an effective field. Refetch public state after save.                                                                  |
| Soul, rules and agents documents                                  | Host settings/file and file_delete                                        | Verify kind, name and UTF-8 byte count. Guard unsaved navigation and disable save after failed load. Host revision support requires host verification. |
| Watchlist, per-chat inheritance, alerts and digest hours          | Protected market writer and host watchlist operations                     | Market file replacements compare previous field values. Preserve unrelated rules and recipients.                                                       |
| Pack toolFooter.icon and labels                                   | PUT /api/characters/:id/footer                                            | Data-pack writer restores original bytes after failed audit or reload. Repository packs refuse updates.                                                |
| Theme, sort and owner credential                                  | Legacy browser keys tolongai-theme, markets.sort and tolongai-token       | Treat sort and theme as presentation. Treat token as a credential. Exclude it from telemetry, URLs and serialized preferences.                         |
